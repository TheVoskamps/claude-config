# One Place

Read before writing a sentence into any Markdown file in a repo —
instruction Markdown a session loads and human documentation alike.
That is this guide's whole remit.

## A fact lives in exactly one file

Every fact the diff states has one owner. Before writing a sentence
that states a fact, find the file that owns it; when the owner is
another file, the sentence is not written.

## A self-checking qualifier replaces an enumeration

Every set the diff refers to is written as the condition its members
satisfy — "where the plugin ships a README that rosters its contents"
— and never as the list of things that satisfy it today.

## A file never name-drops its consumers

No sentence the diff adds names who reads the file, calls into it, or
depends on it. What a file provides is its contract; who consumes it
is not.

## No file points at another file

No sentence the diff adds sends the reader to another file, except a
`CLAUDE.md` routing-table entry or a guide's lead naming its own
per-repo extension file. Nowhere else does a pointer help — an
always-loaded file is already in context, and an on-demand file is
reached by the trigger and kernel its routing-table entry carries.

Naming a file as the subject a rule governs is not pointing at it.

## A pointer names the file and never a heading

An allowed pointer names a path and stops there. Headings get renamed
and reworded; the path is what a reader opens.

## A duplicate is deleted rather than reconciled

For every duplicated or enumerated fact a review finds, the finding
is "delete the copy" or "state the condition instead" — never
"complete the list" or "synchronize the copies".
