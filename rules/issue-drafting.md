# Issue Drafting

Read this file before drafting or filing an issue, in any repo and
through any path — the `issues:issue-create` skill, a bare
`gh issue create`, or prose handed to a human to file.

## The wiring

Invoke `irene-tools:writing-issues` before composing any issue body,
and follow it. That skill owns the doctrine — an issue is a business
problem statement a senior engineer absorbs in one quick pass, and
the technical direction lives in a spec — so it is cited here rather
than restated, per the cite-a-rule habit the skill itself teaches.

If the skill is unavailable in the session (plugin not installed),
say so rather than improvising its content, and still hold the gate
below.

## The gate

Never draft an issue until the human has provided or reviewed: the
person and the moment, the workflow impact, the worst day in business
terms, and the priority with its evidence. Missing item → ask, never
infer. This is the skill's one hard rule, carried here so it binds
even when the skill body never loads.
